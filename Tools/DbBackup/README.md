# DbBackup — Firebase RTDB 시간별/일별 백업

무료 요금제(Spark)라 Firebase 자동 백업이 없어서 만든 도구다. 2026-09-18 콘솔에서 루트를 잘못 덮어써
전 계정 세이브가 사라졌는데 되돌릴 방법이 없었던 사고가 계기다.

- 서버 PC에서 **매시 정각** 윈도우 작업 스케줄러로 한 번씩 실행한다(상주하지 않는다).
- DB를 **DB 밖(서버 PC 디스크)** 에 저장한다. 같은 DB 안에 두면 루트 덮어쓰기 한 번에 백업도 같이 사라진다.
- **읽기 전용.** DB에 절대 쓰지 않는다. 복원은 사람이 한다.

## 폴더 구조

```
{backupRoot}/
  hourly/2026-09-18/00.json … 23.json   정각마다 새 파일(당일 사고 대비)
  daily/2026-09-17.json                 그날 마지막 정상 시간본(날짜가 지나면 다음 실행에서 확정)
  characters/2026-09-17/{uid}_{uniqueId}_{이름}.json   캐릭터 하나만(복원용)
  backup.log                            실행·검증 결과
```

검증(루트에 Users와 캐릭터 존재, 직전 백업 대비 캐릭터 수 급감 여부)을 통과한 것만 저장한다.
망가진 DB가 정상 백업을 밀어내지 않게 하기 위함이다. CharacterNames가 없으면 저장은 하되 로그에 경고를 남긴다.

일일본 확정은 자정 한 번에 기대지 않는다. 매 실행마다 "지난 날짜인데 hourly 폴더가 남은 날"을 찾아 확정하므로,
자정에 서버 PC가 꺼져 있었어도 다음 실행에서 밀린 날이 확정된다.

종료 코드: 0 = 저장 성공, 1 = 검증 실패 또는 실행 오류(backup.log 확인), 2 = 설정 오류.

## 설치 (서버 PC, 1회)

1. **서비스 계정 키 발급**
   Firebase 콘솔 ▸ 프로젝트 설정 ▸ 서비스 계정 ▸ **새 비공개 키 생성** → JSON 파일이 내려받아진다.
   - 이 파일은 **DB 전체를 읽고 쓸 수 있는 관리자 권한**이다. 저장소 밖(예: `D:/ProjectS-Secrets/`)에만 두고,
     메신저·git·로그 어디에도 올리지 않는다. 유출되면 콘솔에서 해당 키를 즉시 삭제하고 새로 발급한다.
2. **빌드**: `dotnet publish -c Release -o D:/ProjectS-Tools/DbBackup`
3. **설정**: 출력 폴더의 `dbbackup.config.example.json`을 복사해 `dbbackup.config.json`으로 만들고 경로를 채운다.
4. **수동 1회 실행**으로 `backup.log`와 `hourly/`에 파일이 생기는지 확인한다.
5. **작업 스케줄러 등록**: 트리거 "매일 00:00, 1시간마다 반복, 기간 무기한", 동작 `ProjectSDbBackup.exe`,
   "사용자의 로그온 여부에 관계없이 실행", 시작 위치 = exe 폴더.

## 복원 (사람이 함)

**복원 전에 반드시 지금 상태를 먼저 내보내기** 한다(되돌리기를 되돌릴 수 있게).

| 상황 | 파일 | 콘솔에서 가져오는 위치 |
|---|---|---|
| 캐릭터 하나가 망가짐 | `characters/{날짜}/…json` | 그 캐릭터 노드 `Users/{uid}/Characters/{uniqueId}` |
| 당일 사고 | `hourly/{오늘}/{시}.json` | 루트(전체 복원일 때만) |
| 며칠 전으로 전체 | `daily/{날짜}.json` | 루트 |

콘솔 가져오기는 **지금 선택된 노드를 통째로 교체**한다. 가져오기 전에 위쪽 경로 표시줄을 꼭 확인한다.
