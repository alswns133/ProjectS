# ProjectS ID 넘버링 규칙 (v1)

> 데이터 테이블(JSON)의 ID 부여 규칙을 하나로 통일한 문서. **모든 데이터는 이 규칙을 따른다.**
> 확정: 2026-07-28. 문의/변경은 이 문서를 갱신하고 팀에 공유한다.

## 원칙

1. **각 테이블은 독립 딕셔너리** → ID는 자기 테이블 안에서만 유일하면 된다(다른 테이블과 숫자가 겹쳐도 무방).
2. **ID 자릿수·앞자리에 의미를 인코딩한다(스마트 ID).** 시트에서 눈으로 분류가 보이게.
3. **같은 사실을 ID와 컬럼에 둘 다 두면, Validate가 둘의 일치를 검사한다.** 오타는 로딩 시점에 걸러 조용히 통과하지 못하게 한다("구조가 규칙을 만든다"). → 각 테이블 `Validate(out error)`에 넘버링 검사를 넣는다.
4. 표기: `[의미N]`은 N자리를 뜻한다. 예: `[던전1]`=1자리, `[레벨3]`=3자리(0 채움).

범례: **기존** = 이미 만들어진 데이터에서 추출(변경 금지) / **신규** = 이번에 확정 / **확장** = 콘텐츠 나올 때 번호만 추가.

---

## 1. 캐릭터 — 1자리 · **기존**

| 값 | 캐릭터 |
|---|---|
| 1 | 검사 (SW) |
| 2 | 거너 (GN) |

## 2. 스킬 — 공용 1자리 / 캐릭터 3자리 · **기존**

- **공용 액션(1자리)**: `1`=평타, `2`=피니시, `3`=우클릭 강공격
- **캐릭터 스킬(3자리)** `[캐릭터1][스킬2]`
  - 캐릭터: 1=검사, 2=거너
  - 스킬: `01`·`02`·`03` = 스킬, `04` = 각성기(궁극기)

예) `102` = 검사 스킬2 · `104` = 검사 각성기 · `204` = 거너 각성기

## 3. 몬스터 — 4자리 `[던전1][난이도1][순번2]` · **기존**

| 자리 | 의미 | 값 |
|---|---|---|
| 1 | 던전 | 1, 2, … |
| 2 | 난이도 | 1=노말 · 2=하드 · 3=매니악 |
| 3~4 | 순번 | `01`~`08` 일반, `09` 보스 |

예) `1101` = 던전1·노말·A · `1109` = 던전1·노말·보스 · `2301` = 던전2·매니악·A

## 4. 던전/스테이지 — 2자리 `[던전1][난이도1]` · **신규**

몬스터 ID의 앞 2자리와 동일하게 맞춘다(몬스터 `1101` → 스테이지 `11` 소속).
Clear 목표(퀘스트 4장)의 대상 ID로 쓴다.

| 값 | 의미 |
|---|---|
| 11 / 12 / 13 | 던전1 노말 / 하드 / 매니악 |
| 21 / 22 / 23 | 던전2 … |
| 99 | 레이드(최종 단일 컨텐츠) |

## 5. 지역 — 2자리 · **신규**

퀘스트 ID의 지역 자리에 쓰는 그룹 코드(외래키 아님, 조직용).

| 값 | 지역 |
|---|---|
| 01 | 시작 마을 |
| 02 | 던전1 지역 |
| 03 | 던전2 지역 |

## 6. 아이템 — 6자리 `[분류1][등급1][종류1][레벨·순번3]`

| 자리 | 의미 | 값 |
|---|---|---|
| 1 | 분류 | **1무기·2방어구**(기존) / **3소비·4재료**(신규) |
| 2 | 등급 | 0노말·1매직·2레어·3유물 (소비/재료는 등급 없으면 0) |
| 3 | 종류 | 아래 분류별 표 |
| 4~6 | 레벨/순번 | 무기·방어구=레벨(`001`~`035`, 실제 레벨 0채움) / 소비·재료=순번(`001`~) |

종류(3번째 자리):

| 분류 | 종류 값 |
|---|---|
| 1 무기 | 1검 · 2총 · *(확장)* |
| 2 방어구 | 1상의 · 2하의 · 3장갑 · 4신발 |
| 3 소비 · **신규** | 1=HP회복 · 2=SG(스킬게이지)회복 · 3=스태미나회복 · 4=버프 · *(확장)* |
| 4 재료 · **신규** | 1=하급 강화재료 · 2=상급 강화재료 · 3=퀘스트 재료 · *(확장)* |

예)
- `101001` = 무기·노말·검·Lv1 *(기존)*
- `211010` = 방어구·매직·상의·Lv10 *(기존)*
- `301001` = 소비·노말·HP회복·순번001 *(신규)*
- `403001` = 재료·노말·퀘스트재료·순번001 *(신규, 예: 약초)*

> 소비/재료는 아직 `ItemData`에 없다. **위 규칙대로 추가하면 됨.** 그 전까지 퀘스트가 아이템을 참조할 땐 실제 존재하는 무기/방어구 ID만 쓴다.

## 7. 퀘스트 — 6자리 `[종류1][지역2][순번3]` · **신규**

| 자리 | 의미 | 값 |
|---|---|---|
| 1 | 종류 | 5=메인 · 6=반복 (앞자리 5·6으로 아이템 1~4와 구분) |
| 2~3 | 지역 | 5장 지역 코드(01마을·02던전1…) |
| 4~6 | 순번 | `001`~ |

**Validate 강제(구현됨, `QuestTable.Validate`)**: 6자리 / 앞자리 5·6 / **ID 종류 ↔ `QuestType` 필드 일치** / 지역·순번 ≥ 1. 어긋나면 그 행은 로딩에서 제외.

예) `501001` = 메인·마을·001 · `601002` = 반복·마을·002 · `502003` = 메인·던전1(02)·003

---

## 8. ID를 쓰지 않는 것

- **재화(골드 등)**: 종류가 적고 고정이라 열거형(`QuestRewardType.Gold` 등)으로 다룬다. 숫자 ID 없음.
- **레벨 도달(Reach) 목표**: 대상 ID = 도달할 레벨 숫자 그대로(1~). 지역 도착형 Reach가 필요해지면 그때 지역 엔티티 ID를 레벨과 안 겹치는 범위로 확정한다.

## 부록: 테이블별 Validate 권장

각 테이블의 `Validate(out error)`에 자기 넘버링 검사를 넣어 오타를 로딩 때 거른다.
현재 퀘스트(`QuestTable`)는 적용 완료. 몬스터·아이템 테이블에도 "ID 자릿수 + ID가 인코딩한 값 ↔ 컬럼(DungeonId/Category 등) 일치" 검사를 넣는 것을 권장한다(같은 사실을 두 곳에 둔 모순을 잡음).
