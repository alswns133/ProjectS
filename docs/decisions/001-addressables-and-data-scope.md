# ADR-001: JSON 테이블과 Addressables 적용 범위

- 상태: 승인됨 (단계적 적용)
- 날짜: 2026-07-15
- 결정자: 팀 논의 (작성: 김민준)

## 배경

프로토타이핑 단계에서는 밸런스 수치(데미지, 쿨타임 등)를 Unity 인스펙터에서 직접 조정해 왔다.
콘텐츠(몬스터·스킬·아이템)가 늘어나면 다음 문제가 예상된다.

- 같은 구조의 데이터가 프리팹마다 흩어져 있어 일괄 밸런스 조정이 어렵고 실수가 생긴다.
- 기획 밸런스 수정에 매번 에디터 작업이 필요하다.
- 모든 리소스를 씬에 직접 참조하면 스테이지가 늘수록 메모리를 내릴 수단이 없다.

사운드(`SoundManager` + `SoundTable`)와 JSON 테이블(`JsonManager` + `IDataRow`)은
이미 Addressables 기반 파이프라인이 있으므로, 나머지 데이터와 에셋의 적용 범위를 정한다.

## 결정

### 1. JSON 테이블로 뽑는 데이터

기준: **기획자가 시트에서 바꾸는 게 자연스러운 값**이거나 **종류(행)가 계속 늘어나는 데이터**.

- 우선순위: 몬스터 스탯 > 스킬(쿨타임·데미지·게이지) > 아이템/드랍 > 퀘스트 텍스트 > 플레이어 스탯.
- 아이템/퀘스트는 처음부터 JSON으로 시작한다(나중에 옮기는 비용이 더 큼).
- 개발 중인 기능은 인스펙터로 완성하고, 수치가 안정되거나 종류가 늘 때 테이블로 옮긴다.

인스펙터에 남기는 것: 프리팹·파티클·Transform 등 참조 전부, 히트박스 배치(애니메이션과 한 몸),
연출 감각 값, 시스템 튜닝 값(속도 평활화, NavMesh 샘플 반경, 회피 우선순위 등).
기획 밸런스가 아닌 "시스템을 굴러가게 하는 나사"는 테이블로 뽑지 않는다.

### 2. Addressables 적용 기준: 자산 종류가 아니라 수명(lifetime)

| 수명 | 대상 예시 | 방침 |
|---|---|---|
| 항상 메모리에 존재 | 플레이어, HUD, 매니저, 코어 UI | Addressables 제외. 직접 참조/씬 배치 |
| 씬/스테이지 단위 교체 | 스테이지별 몬스터·이펙트 프리팹, BGM, 스테이지 데이터 | Addressables. 씬 진입 시 프리로드, 씬 전환 시 일괄 Release |
| 여러 번들이 공유 | 공용 머티리얼·텍스처·셰이더, 공용 몬스터 | "Shared" 그룹 등록 (아래 근거 참조) |

그룹은 "같이 로드되고 같이 내려가는 것끼리" 나눈다.

### 3. 프리팹 로드 구조

- 테이블 행에 Addressables 주소 문자열을 두고, 로더가 `LoadAssetAsync`로 프리팹을 1회 로드해 캐싱한다.
- 인스턴스 생성은 기존 풀링(`PooledSpawner`)에 맡긴다.
- 씬 전환 시 풀 비우기 → 핸들 Release 순서를 지킨다. 구현 본보기: `SoundManager`.

## 검토한 대안

- **`Addressables.InstantiateAsync`로 인스턴스까지 관리** — 기각.
  인스턴스마다 참조 카운트를 관리해야 해서 풀링과 충돌한다. 에셋 로드(핸들 1개)와
  인스턴스 수명(풀)을 분리하는 쪽이 기존 구조와 맞는다.
- **머티리얼/셰이더를 개별 주소로 로드** — 기각.
  프리팹 로드 시 의존성으로 자동 포함되므로 코드에서 개별 로드할 일이 없다.
  Shared 그룹 등록의 목적은 로드가 아니라 **번들 간 중복 포함 방지**다. 공유 에셋이
  미등록 상태면 이를 쓰는 모든 번들에 복제되어 빌드 크기와 메모리가 이중으로 든다.
- **모든 프리팹을 Addressables로 통일** — 기각.
  항상 메모리에 있는 에셋은 내릴 일이 없어 이득이 0이고, 비동기 로드 복잡도만 는다.

## 영향과 후속 작업

- 같은 에셋을 Addressables와 직접 참조로 동시에 쓰지 않는다(빌드에 두 벌 포함됨).
  경계 예시: 몬스터 프리팹은 전부 Addressables, 플레이어처럼 상주하는 것은 직접 배치.
- Addressables Analyze의 **Check Duplicate Bundle Dependencies**를 주기적으로 돌려
  Shared 그룹 누락을 점검한다.
- 첫 적용 대상은 몬스터 스탯 테이블 + 몬스터 프리팹 로더(몬스터 3~4종 시점).
- 전투 중 첫 스폰 히칭이 관찰되면 셰이더 프리워밍(ShaderVariantCollection)을 검토한다.
