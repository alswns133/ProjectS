## 3. 핵심 설계 — 왜 이렇게 짰는가

### 본체 감추기: `SetActive(false)`가 아니라 `Renderer.enabled = false`

오브젝트를 통째로 끄면 **검에 달린 트레일 파티클까지 같이 죽는다.** 렌더러만 끄면 뼈·무기 트랜스폼은 계속
애니메이션되고 파티클도 계속 방출되므로 궤적이 그대로 그려진다. 이 연출의 전제다.

### 복구는 "무조건 켜기"가 아니라 "감추기 직전 상태로"

히트박스 시각화처럼 **원래 꺼져 있던 렌더러**를 연출 후 켜 버리면 각성기 한 번에 판정 박스가 화면에 나타난다.
감추는 순간의 `enabled`/`shadowCastingMode`를 기록했다가 그대로 되돌린다.

### 잔상: 캐릭터 복제가 아니라 `SkinnedMeshRenderer.BakeMesh`

복제(Instantiate)는 Animator·컨트롤러까지 따라와 무겁고, 복제본이 애니메이션을 이어 재생해 "그 순간 포즈로
멈춘 잔상"이 되지 않는다. 구운 메시는 정지한 스냅샷이다.
**본체가 감춰져 있어도 정상 동작한다** — BakeMesh는 렌더러 표시 여부가 아니라 뼈 트랜스폼을 읽는다.

### 잔상 배치: 루트 상대 포즈로 환산 후 목표 포즈에 얹기

파트(몸·무기)를 각각 옮기면 축에서 먼 무기일수록 몸과 어긋난다. 원본을 캐릭터 루트 기준 상대값으로 바꾼 뒤
목표 루트 포즈에 통째로 얹는다. 오프셋과 yaw는 **서로 독립** — 각도를 조정할 때 위치가 따라 튀면 튜닝이 불가능하다.

## 4. 유니티 세팅 현황

### `Player Body Visibility` (세팅 완료)

- `Body Renderers` — **비워둠**(자동 수집). 결과: `mesh`(하루 몸) + `Haru Weapon`(검) 2개
- `Exclude Roots` — **`Hitbox`** 등록. 이걸 넣기 전에는 히트박스 메시 7개가 함께 잡혔다.
- `Keep Shadow While Hidden` — 꺼짐(완전히 사라짐). 켜면 `ShadowsOnly`로 그림자만 남는다.
- `Max Hidden Time` — 6초(안전 복구)

### `Player After Image` (기본 세팅 완료)

- `Ghost Material` — `Haru_Ghost` (URP/Unlit · Transparent · **Additive** · Base Map 비움)
  ※ 색·투명도는 머티리얼이 아니라 컴포넌트의 `Start Color`에서 조절한다. 코드가 매 프레임 `_BaseColor`를 덮어쓴다.
  ※ Additive라 어두운 색은 거의 안 보인다. 또렷한 실루엣이 필요하면 Alpha로 바꿀 것.
- `Color Property` — `_BaseColor`
- `Source Renderers` — **비워둠**. `PlayerBodyVisibility`가 확정한 목록을 그대로 쓴다(제외 설정도 자동 상속).
- `Pose Slots` — **아직 비어 있음** (남은 작업)

## 5. 애니메이션 이벤트

### 이미 붙인 것 (`Power_Attack_End.anim`)

| 이벤트 | 인자 | 위치 |
|---|---|---|
| `OnHideBody` | 없음 | 클립 시작부 |
| `OnShowBody` | 없음 | 클립 막바지 (**마지막 프레임보다 살짝 앞**에 둘 것 — 정확히 끝 프레임이면 전이 타이밍에 씹힐 수 있다) |
| `OnAfterImage` | Float(각도) | 별 꼭짓점 5곳 |

### 남은 것

| 이벤트 | 인자 | 설명 |
|---|---|---|
| `OnAfterImageFadeOut` | 없음 | 별이 완성된 프레임. 떠 있는 잔상을 **전부 동시에** 소멸시킨다 |
| `OnAfterImageAt` | String(슬롯 키) | 지정 위치 잔상. `OnAfterImage`(현재 위치)와 **섞어 쓰지 말 것** — 도형이 어긋나 보인다 |
| `OnAfterImageAnchor` | 없음 | (선택) 기준 좌표계를 이 프레임의 캐릭터 위치·방향으로 고정 |

키의 언더바 차이(`Star_1` vs `Star1`)는 `AnimationEventKey.Normalize`가 흡수한다.
키 오타는 조용히 실패하지 않고 콘솔 경고(`After-image key not found`)가 뜬다.

## 6. 남은 작업

1. **잔상 일괄 소멸 적용**
   `Wait For Fade Signal` 체크 → `Fade Out Duration` 설정(**0이면 한 번에 확 사라짐**) → `OnAfterImageFadeOut` 이벤트 배치.
2. **지정 위치 잔상 세팅**
   `Pose Slots`에 5개(`Star_1`~`Star_5`) 추가 → 씬 뷰 기즈모(하늘색 구체 = 위치, 선 = 바라볼 방향)를 보며 `Offset`/`Yaw Offset` 조정
   → 클립의 `OnAfterImage` 5개를 `OnAfterImageAt`으로 교체.
   `From Anchor`는 기본 켜짐 — 루트모션으로 이동하는 클립에서도 도형이 흔들리지 않는다.
3. **검기 투사체 랜덤 회전 (미적용)**
   `ProjectileSlot`에 `public Vector3 randomRotationRange;` 필드를 추가하고,
   `PlayerCombat.cs`의 `Quaternion rotation = slot.muzzle.rotation * Quaternion.Euler(slot.rotationOffset);` 바로 뒤에서
   범위가 0이 아니면 `UnityEngine.Random.Range`로 굴린 오일러 각을 곱한다(`using System;` 때문에 `Random`은 모호하므로 정규화 필요).
   ※ **판정 박스(`Projectile.hitBoxSize`)도 함께 돌아간다.** 기본값이 `(2, 1, 0.5)`로 가로가 넓은 비대칭 박스라,
   Z를 크게 주면 판정이 세로로 선다. 연출용 흔들림은 10~15도 이내 권장.
   ※ 판정은 고정하고 **비주얼만** 흔들고 싶다면 코드 대신 파티클 시스템 Main → Start Rotation(`Random Between Two Constants`)이 맞다.
4. **최종 플레이 테스트** (아래 7번 체크리스트)

## 7. 테스트 체크리스트

이미 통과한 항목: 감추기/되돌리기, 감춘 중 트레일 유지, 구르기·피격 캔슬 복구, 씬 전환 복구, 연속 사용.

잔상까지 포함해 다시 볼 것:

- [ ] 각성기 도중 구르기·피격·사망 → 본체 복구 + 잔상도 정리되는가
- [ ] 씬 전환(마을↔던전) 중 감춰진 상태 → 복구되는가
- [ ] 각성기 연속 2~3회 → 이전 묶음 잔상이 새 묶음에 섞이지 않는가
- [ ] `OnShowBody` / `OnAfterImageFadeOut` 이벤트를 일부러 지운 상태 → 안전 타임아웃(6초) 경고와 함께 자동 복구되는가

## 8. 함정 모음 (여기서 시간을 뺏겼던 것들)

- **플레이 모드 중 스크립트 컴파일 → NRE 폭주.**
  `Player.get_IsRolling`에서 `NullReferenceException`이 매 프레임 쏟아지면 대개 이것이다. 도메인 리로드로
  직렬화되지 않는 private 필드(`sm` 등)가 null이 되는데 `Awake`는 다시 불리지 않는다.
  **플레이를 정지했다 다시 시작하면 사라진다.** 예방: `Edit > Preferences > General > Script Changes While Playing`
  → `Recompile After Finished Playing`.
- **런타임 생성 `MeshRenderer`의 기본 머티리얼은 URP에서 마젠타.**
  잔상이 보라색으로 나오면 머티리얼이 적용되지 않은 것이다. 슬롯 "개수"만 비교하면 서브메시 1개짜리에서
  개수가 같아 영영 교체되지 않으므로, 머티리얼 자체를 비교해야 한다(현재 코드는 그렇게 되어 있다).
- **같은 GameObject의 컴포넌트끼리는 `Awake` 순서가 보장되지 않는다.**
  `PlayerAfterImage`가 `PlayerBodyVisibility`의 목록을 `Awake`에서 읽으면 아직 비어 있을 수 있어,
  원본 목록 확정을 **첫 사용 시점(`EnsureSources`)** 으로 미뤄 두었다. 이 구조를 되돌리지 말 것.
- **Animation Event 함수 오버로드 금지.**
  Unity가 이름으로 메서드를 찾으므로 같은 이름의 오버로드가 있으면 호출이 깨진다.
  그래서 `OnAfterImage`(Float) / `OnAfterImageAt`(String)로 **이름을 나눴다.**
- **빈 함수명 AnimationEvent.**
  `'Haru' AnimationEvent has no function name specified!` 경고는 Add Event를 눌러놓고 함수를 안 고른 이벤트다.
  실제로 `Power_Attack_Start.anim` 0프레임에 하나 있었고 제거했다. 이벤트를 여러 개 찍을 때 재발하기 쉽다.
- **`Fade Out Duration = 0`** 은 0으로 나누는 계산이 되어 그냥 두면 잔상이 영영 안 사라진다.
  코드에서 진행도를 끝값으로 못박아 처리했다.
