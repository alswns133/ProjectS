## 2. 코드 변경

### 규칙이 바뀐 부분 — `Assets/Scripts/UI/Popups/DeathPopup.cs`

| 항목 | 이전 | 지금 |
|---|---|---|
| ESC 닫기 | 가능 | **차단** (`CanCloseByBack => false`) |
| 부활 기회 | 세션 1회 (`reviveConsumed` bool) | **`ReviveBudget`** — 던전 한 판 1회, 재입장 시 복구 |
| 기회 없을 때 | 부활 버튼만 비활성 | **선택지를 숨기고 자동 마을 복귀** |
| 부활 | 클릭 즉시 | **`reviveDelay`(기본 3초) 카운트다운 후** |
| 마을 복귀 | 클릭 즉시 전환 | **`returnDelay`(기본 5초) 카운트다운 후** |
| 남은 시간 표시 | 없음 | `countdownText` (부활·복귀 공용) |

**ESC를 막은 이유**: 닫히면 `PlayerDeadState`는 스스로 빠져나오지 않는 막다른 상태라, 플레이어가 죽은 채
아무 UI도 없이 조작 불가로 갇힙니다. 창을 다시 부를 방법이 없어 재시작 말고는 탈출 경로가 없습니다.

**부활에 대기를 준 이유**: 죽은 프레임에 곧바로 되살아나면 사망 연출·남아 있는 적 공격과 겹쳐 상태가 꼬이고,
플레이어도 무슨 일이 일어났는지 못 읽습니다. 즉시 부활이 필요하면 `reviveDelay`를 0으로 두면 됩니다.

**유지한 것**: 필드 이름 `reviveButton` / `returnToVillageButton`은 그대로라 **기존 `Bootstrap.unity` 연결은
끊기지 않습니다.** 마을 복귀 전에 `Player.Revive()`를 부르는 기존 처리도 그대로 살렸습니다 —
`VillageGather.Enter`의 `RefillOnSceneEnter`는 죽어 있으면 회복을 건너뛰므로, 이걸 빼면 마을에 HP 0으로 도착합니다.
(시안에는 이 처리가 빠져 있었습니다.)

### 새로 생긴 직렬화 필드

전부 **선택 사항**입니다. 비워도 기능은 정상 동작하고, 연출만 안 나옵니다.

| 필드 | 용도 |
|---|---|
| `messageText` | 안내 문구 (선택 중 / 부활 대기 / 복귀 대기에 따라 문장이 바뀜) |
| `countText` | 잔여 부활 기회 `n / 1` |
| `countdownText` | 남은 초. 대기 중에만 켜짐 |
| `choiceGroup` | 선택 버튼 묶음. 없어도 버튼을 개별로 토글함 |
| `titleFx` | 타이틀 글리치 연출. **팝업이 열릴 때(`OnShow`) 처음부터 재생**한다. 비워두면 자식에서 자동으로 찾음 |
| `chooseMessage` / `revivingMessage` / `returningMessage` / `autoReturnMessage` | 문구 |
| `reviveDelay` / `returnDelay` | 대기 시간(초) |

## 3. `Bootstrap.unity`에서 해야 할 일

### 방법 A — 툴 실행 (권장, 1분)

`Bootstrap.unity`를 열고 **`Tools ▸ ProjectS ▸ 사망 팝업 → 정식(DeathPopup)으로 전환`** 실행 후 Ctrl+S.
멱등이라 여러 번 실행해도 안전하고, **이미 연결된 필드와 이미 있는 오브젝트는 건드리지 않습니다.** Ctrl+Z로 되돌아갑니다.

현재 `Bootstrap.unity`의 팝업에 대해 툴이 하는 일:

- 딤 배경(Image) 추가 — 지금은 배경이 없어 뒤 화면이 그대로 보이고 클릭도 통과합니다
- `TitleText`("사망") 생성 + **글리치 연출(`GlitchTextFx`) 부착 및 셰이더 슬롯 배선**
- `MessageText` · `ReviveCountText` · `CountdownText` 생성 후 각 필드에 연결
- 한글 폰트(Paperlogy) 자동 배선 — 기본 폰트로 두면 한글이 네모로 나옵니다

좌표는 중앙 720px 폭이라 좌우 끝에 있는 기존 버튼과 겹치지 않습니다.
`DeathPopupTrigger`와 팝업 배치(UIManager 직속 · 자체 Canvas)는 이미 맞게 되어 있어 그대로 통과합니다.

팝업 오브젝트(`UIManager/DeathPopup`) 아래에 TMP 텍스트 4개를 만들고 인스펙터에서 연결:

## 4. 배치 제약 — 옮기면 조용히 깨지는 것들

`Bootstrap.unity`는 이미 맞게 되어 있지만, 나중에 팝업을 옮길 때를 위해 남깁니다.

- **팝업은 UIManager 직속이어야 합니다.** `DeathPopupTrigger`는 `RegisterPopup`을 부르지 않고
  UIManager의 자동 수집(`Awake`의 `GetComponentsInChildren<BasePopup>`, **자기 자식만**)에만 의존합니다.
  밖으로 나가면 죽어도 "팝업이 없음" 경고만 남고 창이 뜨지 않습니다.
- **팝업은 자기 Canvas를 가져야 합니다.** UIManager는 UI 계층이 아니라 그냥 Transform이라,
  Canvas가 없으면 켜져 있어도 화면에 아무것도 안 나옵니다.
- **HUD(BasePanel) 아래에 두면 안 됩니다.** HUD가 닫히면 GameObject째 꺼져 팝업도 함께 사라집니다.
- **트리거는 항상 켜져 있는 오브젝트에.** 꺼지면 `OnDisable`로 구독이 풀려 아무 경고 없이 조용히 실패합니다.

## 5. 테스트 방법

씬에 `DeathTester`를 붙이거나 `Tools ▸ ProjectS ▸ Setup Death Test (current scene)` 실행 후,
재생 → 인스펙터 컨텍스트 메뉴(⋮)를 번호 순서로:

- **부활 분기**: `0`(HUD 열기) → `1`(기회 채우기) → `3`(죽이기) → 팝업에서 '부활' → 3초 뒤 부활
- **자동 복귀 분기**: `0` → `2`(기회 비우기) → `3` → 선택지 없이 카운트다운 후 마을 복귀
- **ESC 확인**: 팝업이 떠 있을 때 ESC → 닫히지 않아야 정상

★ `0`을 먼저 하지 않으면 `3`에서 `FillGauge`가 NullReference로 터지고, **그 예외가
`PlayerStats.TakeDamage` 한가운데서 나기 때문에 `FirePlayerDied()`가 실행되지 않습니다** —
"죽었는데 창이 안 뜬다"의 진짜 원인이 이것입니다.

## 6. 함정 모음

- **부활 기회는 `DungeonGather.Enter`에서만 채워집니다.** HUD 씬을 단독 재생하면 기회가 0이라
  첫 사망부터 자동 복귀 분기로 빠집니다. 고장이 아니라 정상 동작입니다.
- **카운트다운은 `Time.unscaledDeltaTime` 기준입니다.** 사망 연출로 `timeScale`을 낮춰도 늘어지지 않습니다.
- **대기 중에는 두 버튼을 모두 숨기고 입력을 막습니다.** 부활 대기 중 마을 복귀가 눌리면
  이동과 부활이 동시에 성립해 마을에서 부활 모션이 도는 사고가 납니다.
- **팝업을 켠 채 저장하면** 재생하자마자 사망 창이 화면을 덮습니다. `BasePopup`은 UIManager가
  `Show`할 때 켜지는 것을 전제로 합니다.
- **씬에 `EventSystem`이 없으면** 창은 떠도 버튼이 눌리지 않습니다. 원인이 팝업 쪽으로 보여 헤매기 쉽습니다.

## 7. 씬 머지 주의

`.gitattributes`에 `*.unity merge=unityyamlmerge` 선언은 있으나, **로컬 git에 그 드라이버가 등록돼 있지 않으면
선언은 효력이 없고 일반 텍스트 3-way 머지가 돌아갑니다.** `git config --get merge.unityyamlmerge.driver`가
비어 있으면 아래를 한 번 실행해 주세요 (Unity 6000.3.8f1 기준).

```
git config --global merge.unityyamlmerge.name "Unity SmartMerge"
git config --global merge.unityyamlmerge.driver "'C:/Program Files/Unity/Hub/Editor/6000.3.8f1/Editor/Data/Tools/UnityYAMLMerge.exe' merge -p --force --fallback none %O %B %A %A"
git config --global merge.unityyamlmerge.recursive binary
```

## 8. 남은 것 · 판단이 필요한 것

1. **`Bootstrap.unity` 반영** (3번) — 프로그래머 쪽에 맡깁니다.
2. **부활 버튼 라벨 `"부활(1회성)"` 수정** — 규칙이 바뀌어 문구가 맞지 않습니다.
3. **대기 시간 튜닝** — 부활 3초 / 복귀 5초는 임시값.
4. **시안 코드 정리 여부** — `DeathPopupPrototype` · `DeathPresenter` · `DeathPopupBuilder`는
   규칙 이관이 끝나 지워도 됩니다. 지우면 `DeathPopupOfficialSwitch`의 시안 변환 경로도 함께 정리해야 합니다
   (`ReviveBudget`은 `DungeonGather`가 쓰므로 **남겨야 합니다**).
5. **팝업 프리팹화 제안** — 지금 사망 팝업은 세 씬(`Bootstrap`, `Bootstrap(Test)`, `HUD(TH) 2`)에
   각각 손으로 만들어져 있고, 그래서 씬마다 Canvas 유무·부모·구성이 어긋나 있었습니다.
   프리팹 하나를 세 씬이 참조하면 이 종류의 불일치가 구조적으로 사라지고, UI 수정이 씬 diff가 아니라
   프리팹 diff로 남아 씬 충돌도 거의 없어집니다.
   `Bootstrap.unity` 팝업 트리(24개 fileID)를 밖에서 참조하는 것은 **UIManager의 자식 목록 한 줄뿐**이라
   끊길 참조가 없다는 것까지 확인했습니다. 다만 **전환 커밋 자체는 씬을 크게 건드리므로** 판단이 필요합니다.
