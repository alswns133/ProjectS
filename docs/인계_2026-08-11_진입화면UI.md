# 인계 문서 — 진입 화면 UI (캐릭터 선택 · 클래스 선택 · 캐릭터 생성)

**작업일**: 2026-08-11 · **브랜치**: `develop-xogk2222` · **작업자**: TH

`진입 화면 UI 기획서 v0.2`의 3-2 / 3-3 / 3-4를 **UI 계층·뷰 컴포넌트·프리팹까지** 만들었습니다.
**데이터와 서버 연결은 일부러 손대지 않았습니다** — 로스터 로드·생성·삭제·씬 전환은 프로그래머 쪽 영역이라
뷰가 이벤트만 던지고 끝나도록 경계를 그었습니다. 요청 드릴 작업은 4번에 정리했습니다.

작업 씬은 `Assets/Scenes/TH/CharacterSelect(TH).unity` **한 곳뿐**이고, 다른 씬은 건드리지 않았습니다.

## 3. 뷰 API — 붙이실 지점

전부 `ProjectS.UI` 네임스페이스, `Assets/Scripts/UI/Entry/` 아래에 있습니다.
**어떤 뷰도 Firebase·GameSession·씬 전환을 알지 못합니다.**

### `CharacterSelectPageView`

```csharp
IReadOnlyList<CharacterSlotView> Slots     // 인덱스 = 슬롯 번호
Button QuitButton, OptionButton
RawImage ModelViewport
int SelectedIndex                          // 없으면 -1
void SetVersion(string version)
void SetSelectedIndex(int index)           // -1 = 전체 해제
void ClearSelection()
```

### `CharacterSlotView` (슬롯 카드 1장)

```csharp
event Action<int> OnSelected          // 채워진 카드 본체 클릭
event Action<int> OnCreateRequested   // 빈 카드 클릭 (신규 생성 진입)
event Action<int> OnStartRequested    // 게임 시작
event Action<int> OnDeleteRequested   // × 삭제

void SetCharacter(int index, Sprite portrait, string name, int level, string subInfo)
void SetEmpty(int index)
void SetSelected(bool selected)
int Index; bool IsEmpty; bool IsSelected
```

**세이브 데이터를 받지 않고 표시값만 받습니다.** 접속 시 `GameSession`에 담아야 하는 건
서버가 준 `CharacterSaveData` **인스턴스 그 자체**라(uniqueId가 Firebase 노드 키), 뷰가 그걸 들고 있으면
복사본을 담는 실수가 생깁니다. 인덱스 → 캐릭터 매핑은 컨트롤러가 가져가 주세요.

### `ClassSelectPageView`

```csharp
event Action<int> OnClassClicked      // 0 = ClassWarrior, 1 = ClassGunner
Button PrevButton, SelectButton
int SelectedIndex                     // 없으면 -1

void ShowIntro(int index, string info, Texture video = null)
void ClearSelection()
```

### `CharacterCreatePageView`

```csharp
event Action<string> OnCreateRequested   // 인자 = 다듬어진 이름
Button PrevButton
RawImage ModelViewport
string CharacterName

void ClearName()
void SetHint(string message)             // 서버 응답을 인라인으로 쓰고 싶을 때
```

### `PopupLayerView`

```csharp
void ShowConfirm(string message, string subMessage, string confirm, string cancel,
                 Action confirmed, Action cancelled = null)
void ShowAlert(string message, Action closed = null)
void SetBusy(bool busy)
void CloseAll()
bool IsAnyOpen
```

삭제 2단계는 1단계 확인 콜백에서 `ShowConfirm`을 한 번 더 부르면 됩니다.

```csharp
popupLayer.ShowConfirm("캐릭터를 삭제하시겠습니까?", null, "예", "아니오", () =>
    popupLayer.ShowConfirm("정말 삭제하시겠습니까?", "삭제 후 복구 불가", "예", "아니오", () =>
    {
        popupLayer.SetBusy(true);
        // 삭제 요청 → 응답에서 반드시 SetBusy(false)
    }));
```

## 4. 요청 목록

### 4-1. 캐릭터 선택 컨트롤러

슬롯 이벤트를 받아 로스터를 다루는 주체가 없습니다. 대략 이런 일을 합니다.

- 진입 시 로스터 로드 → 6칸에 `SetCharacter` / `SetEmpty`
- `OnSelected` → `SetSelectedIndex` + `ModelRoot`의 캐릭터 프리팹 교체
- `OnStartRequested` → `GameSession.SetSelectedCharacter` → 게임 씬 로드
- `OnDeleteRequested` → 2단계 확인 → 삭제 → 목록 갱신
- `OnCreateRequested` → `Page_Class`로 전환

**★ 로드 실패(`null`)와 캐릭터 0개(빈 리스트)를 반드시 구분해 주세요.**
실패를 0개로 오해해 빈 슬롯 6칸을 열어주면 유저가 이미 있는 캐릭터를 중복 생성합니다
(폐기 예정인 `CharacterSelectUI.cs`의 주석에 실제 사고 기록이 있습니다).
실패 상태에서는 슬롯을 그리지 말고 재시도만 노출하는 쪽이 맞습니다.

### 4-2. 로스터 서비스 (`ICharacterRoster` 같은 경계)

지금 폐기 예정 코드는 UI가 `FirebaseManager`를 직접 부릅니다. 그러면 로그인 없이 이 씬만 열어
배치를 확인하는 게 불가능합니다. `GameSession`이 이미 "게임플레이는 백엔드를 모른다"를 지키고 있으니
같은 선을 UI 쪽에도 그어 주시면 좋겠습니다. 목 구현으로 씬 단독 테스트가 가능해집니다.

### 4-3. `CharacterClassCatalog` (ScriptableObject)

`characterType` → 표시명 · 초상화 Sprite · 프리뷰 프리팹 · 이명/나이/무기/시작 위치 텍스트.

**이 씬에는 `JsonManager`가 없어(Bootstrap 전용) 테이블을 읽을 수 없습니다.**
프리팹·스프라이트 참조는 CLAUDE.md 데이터 방침상 어차피 인스펙터 대상이고요.
에셋 하나가 `Page_Select`의 초상화와 `Page_Class`의 소개 텍스트를 동시에 먹입니다.
선례: `MinimapData`.

### 4-4. 페이지 전환

`Page_Select` ↔ `Page_Class` ↔ `Page_Create` 를 켜고 끄는 주체가 없습니다.
씬 전환이 아니라 같은 씬 안의 오브젝트 토글입니다.
생성 완료 후에는 기획서대로 `Page_Select`로 복귀시켜 주세요.

### 4-5. `ModelRoot`에 캐릭터 프리팹 로드

`CharacterStage/ModelRoot`가 비어 있어 지금은 프리뷰가 단색입니다.
선택 캐릭터 / 선택 클래스에 따라 프리팹을 갈아끼워 주세요.

### 4-6. ENTER 단축키

카드 안 `게임 시작` 버튼 라벨에 `[ENTER]`를 박아 뒀지만 키 입력 처리는 없습니다.
선택된 슬롯이 있을 때만 동작해야 하고, 팝업이 떠 있거나 `BusyBlocker`가 켜져 있으면 막아야 합니다.

### 4-7. 버전 문자열

`CharacterSelectPageView.SetVersion()`으로 넣어 주세요. 지금은 `v0.1.0` 하드코딩입니다.

### 4-8. 환경설정 팝업 (기획서 3-5)

미착수입니다. `OptionButton`은 만들어 뒀지만 아무 데도 연결돼 있지 않습니다.

### 4-9. `FirebaseManager.DeleteCharacter` 보완 ★

`Users/{uid}/Characters/{id}`만 지우고 **`CharacterNames/{이름}` 예약을 지우지 않습니다.**
그 결과 **삭제한 캐릭터의 이름을 다시 쓸 수 없습니다.**

크래시나 데이터 손실은 없지만, 삭제 UI를 붙이는 순간 바로 드러나는 증상입니다.
생성 때처럼 멀티패스 업데이트로 두 경로를 한 번에 지우면 됩니다. 삭제할 캐릭터의 `name`이 필요해서
시그니처에 이름을 더하거나 내부에서 노드를 한 번 읽는 선택이 필요합니다.

> 참고: 현재 `DeleteCharacter`는 호출부가 없어 지금 이 순간의 영향은 0입니다.

## 5. 연출과 의도 — 고치기 전에 확인할 것

버그처럼 보이지만 의도한 동작들입니다.

### 슬롯 카드 높이가 선택해도 변하지 않는다

카드 높이는 **120 고정**이고, 선택 시 바뀌는 것은 구분선 아래 `ActionArea`의 **내용뿐**입니다
(비선택 = 보조 정보, 선택 = 게임 시작 + 삭제).

카드가 세로로 펼쳐지는 아코디언을 검토했다가 접었습니다. `VerticalLayoutGroup` 안에서 높이를 바꾸면
매 프레임 리빌드가 돌고, 늘어난 만큼 아래 카드가 밀려 **커서 밑의 카드가 바뀌어 엉뚱한 캐릭터가 선택**되며,
에디터에서 최종 배치를 볼 수 없게 됩니다. 높이를 고정하면 이 셋이 전부 사라집니다.

→ `ActionArea`에 `LayoutGroup`이나 `ContentSizeFitter`를 붙이지 말아 주세요.

### 게임 시작 버튼이 하단이 아니라 카드 안에 있다

기획서 3-2 ③은 하단 중앙이지만, 하단 버튼이 많다는 판단으로 카드 안으로 옮겼습니다.
"이 캐릭터로 시작한다"는 대상 지시도 강해집니다. 하단에는 종료·환경설정·버전만 남았습니다.

### 슬롯이 8개가 아니라 6개다

기획서는 8개지만 클래스가 2종뿐이라 6개로 줄였습니다.
덕분에 카드를 120까지 키울 수 있었고(8개였다면 42), 초상화가 들어갈 자리가 생겼습니다.
`6 × 120 + 간격 60 = 780` 으로 스크롤 없이 들어갑니다. 카드 높이 상한은 130입니다.

### 삭제 확인에서 ESC가 "아니오"로 동작한다

파괴적 행동이라 ESC는 항상 안전한 쪽에 붙였습니다. 알림 팝업은 선택지가 하나뿐이라 ESC = 확인입니다.

### `BusyBlocker`가 팝업보다 **위**에 있다

처음엔 아래에 뒀는데, 그러면 팝업 버튼이 차단막을 뚫고 눌려 같은 요청이 두 번 나갑니다.
`SetBusy(true)`에서 한 번 더 `SetAsLastSibling()`을 부르는 것도 같은 이유입니다.

### 딤을 팝업 각자가 아니라 `PopupLayerView`가 관리한다

삭제 1단계 → 2단계처럼 팝업이 팝업을 이어 열 때, 각자 딤을 껐다 켜면 그 사이 한 프레임이 밝아져 번쩍입니다.

### 클래스 선택은 아무것도 안 골라진 상태로 시작한다

일러스트 두 장이 가운데 있어 허전하지 않습니다. 고르면 반대쪽이 어두워지고 그 자리에 소개 패널이 열립니다.
**`SelectButton`은 그때까지 잠겨 있습니다** — 안 잠그면 선택 없이 다음 단계로 넘어갑니다.

### 소개 패널이 좌우로 움직이지 않고 껐다 켜진다

이동 연출은 눈에 거슬려서 뺐습니다. 패널 하나를 `IntroSlot_Left` / `IntroSlot_Right` 중
반대편 슬롯으로 `SetParent`한 뒤 다시 켭니다. 두 슬롯이 좌우 대칭이라 앵커 값이 그대로 따라가
별도 배치 코드가 없습니다.

등장 연출(TV 전원)은 `SetActive(false → true)` 시 Animator가 기본 상태부터 다시 재생되는 성질을 이용합니다.
**재생 코드가 없는 게 정상입니다.** 클립의 `Loop Time`은 꺼져 있어야 하고,
`updateMode`는 `UnscaledTime`이라 `timeScale`이 0이어도 돕니다.

### 같은 클래스를 다시 눌러도 아무 일이 없다

`ShowIntro`가 같은 인덱스면 즉시 반환합니다. 0.15초짜리 연출이 연타마다 재생되면 깜빡거려 보입니다.

### 회전 화살표가 뷰포트 rect 바깥에 있다

겹치면 그 자리에서 드래그를 시작할 때 버튼이 입력을 먼저 먹어 회전이 걸리지 않습니다.

### 드래그와 화살표가 같은 컴포넌트를 거친다

각자 각도를 들고 있으면 드래그로 돌린 뒤 화살표를 누르는 순간 원래 각도로 튑니다.
둘 다 `ModelViewportRotator`의 현재 각도에 더합니다. 드래그 방향이 반대로 느껴지면
`OnDrag`의 부호 하나만 뒤집으면 됩니다.

### 생성 페이지를 나가면 모델 회전이 초기화된다

`CharacterCreatePageView.OnDisable`에서 `ResetRotation()`을 부릅니다.
스테이지를 `Page_Select`와 공유하므로, 안 되돌리면 선택 화면의 캐릭터가 뒤통수를 보입니다.

### 이름 힌트가 빈 필드에서는 안 뜬다

아무것도 안 쳤는데 "2자 이상 입력하세요"가 먼저 떠 있으면 잔소리처럼 보입니다.
버튼은 그 상태에서도 잠겨 있어 기능상 문제는 없습니다.

### 생성 버튼 잠금은 로컬 조건만 막는다

| 조건 | 판정 시점 | 처리 |
|---|---|---|
| 2자 미만 · 금지문자 · 공백 | 입력 즉시 | 버튼 잠금 + `NameHintText` |
| 12자 초과 | 입력 자체를 막음 | `characterLimit` |
| **이름 중복** | 서버 응답 | 버튼은 눌림 → `AlertPopup` |
| 생성 실패 | 서버 응답 | 버튼은 눌림 → `AlertPopup` |

중복은 눌러봐야 아는 조건이라 버튼 비활성으로는 못 막습니다. 그래서 `AlertPopup`이 따로 있습니다.

## 6. 배치 제약 — 옮기면 조용히 깨지는 것

- **`ActionArea`·`IntroSlot_*`에 레이아웃 컴포넌트를 붙이지 말 것.** 자식 토글/스케일 애니메이션과
  값이 부딪힙니다.
- **`SlotList`에 `Mask`·`ScrollRect`·`ContentSizeFitter`를 붙이지 말 것.** 6칸이 스크롤 없이 들어가고,
  붙이면 리빌드만 늘어납니다.
- **`SlotList`는 `childControlHeight = true` / `childForceExpandHeight = false`.**
  후자가 true면 남는 공간을 카드가 나눠 가져 높이 120 고정이 깨집니다.
- **`IntroPanel`의 pivot은 (0.5, 0.5).** (0, 1)이면 좌상단에서 펼쳐져 전혀 다른 연출이 됩니다.
- **`Page_Create`의 `ModelViewport`는 `raycastTarget`이 켜져 있어야 합니다.** 꺼지면 드래그 회전이 죽습니다.
  (`Page_Select`의 뷰포트는 반대로 꺼져 있습니다 — 클릭받을 일이 없어서.)
- **`CharacterStage`는 원점에서 y −1000에 있습니다.** 다른 씬 오브젝트가 프리뷰 카메라에 찍히지 않게 한
  **임시 방편**입니다. 전용 레이어를 만들어 컬링 마스크로 가르는 편이 확실한데, 레이어 추가가
  프로젝트 설정 변경이라 제가 임의로 하지 않았습니다. 판단 부탁드립니다.

---

## 7. 아트 넣을 때 해야 할 것

클래스 선택의 일러스트 두 장은 지금 **단색 자리표시자**입니다.
대각선 경계는 UI가 아니라 **PNG의 알파**로 만드는 구조라, 아트가 나오면
`IllustWarrior` / `IllustGunner`의 Source Image에 꽂으면 됩니다. 그다음 두 가지가 필수입니다.

1. 스프라이트 텍스처의 **Read/Write Enabled** 켜기
2. 두 `Image`의 **`Alpha Hit Test Minimum Threshold`를 0.1로** 올리기

지금은 0입니다. 스프라이트 없이 켜면 클릭 시 예외가 날 수 있어 미뤄뒀습니다.
**이 값을 안 올리면 대각선 경계 근처에서 왼쪽 그림을 눌렀는데 오른쪽이 선택됩니다.**

초상화(`CharacterSlotView.SetCharacter`의 첫 인자)도 아직 없습니다. `null`을 넣으면 초상화 칸이 숨습니다.

## 8. 알아두실 것 하나 — 이름 규칙이 두 곳에 있습니다

`CharacterCreatePageView`의 `MinNameLength` · `MaxNameLength` · `ForbiddenChars`는
`FirebaseManager.IsValidName`과 같은 규칙의 **로컬 사본**입니다.
즉시 피드백을 하려면 사본이 불가피한데, 한쪽만 고치면 UI를 통과시켜 놓고 서버에서 실패하는 상태가 됩니다.
서버 규칙을 바꾸실 때 같이 봐 주세요.
